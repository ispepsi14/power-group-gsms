## 1. โปรเจกต์นี้คืออะไร

ระบบจัดการอู่ซ่อมรถ (Garage Service Management System) + แคตตาล็อกอะไหล่
สำหรับอู่ **POWER GROUP** ในประเทศไทย

**ขนาดงานจริง:** รับรถ 20–30 คัน/วัน · ช่องซ่อม 12 ช่อง (H1–H11 + ตั้งศูนย์)

**อุปกรณ์ที่ใช้:** iPhone × 4, iPad × 1, คอมพิวเตอร์ × 2 — **ต้องซิงค์กันแบบเรียลไทม์ทุกเครื่อง**

### ขั้นตอนการทำงานจริงของอู่ (สำคัญมาก — ทุกฟีเจอร์ออกแบบตามนี้)

```
1. รับรถ      → กรอกคิว / ทะเบียน / ลูกค้า / อาการ / รูป / เวลาซ่อมโดยประมาณ
                 (ยังไม่ใส่รายการอะไหล่)
2. พิมพ์ใบรับรถ → ส่งต่อให้ช่างตรวจเช็ค
3. ช่างตรวจเช็ค → กลับมาใส่รายการอะไหล่ที่ต้องเสนอราคา
4. พิมพ์ใบเสนอราคา → มีลายเซ็น 3 ช่อง: ผู้ตรวจเช็ค / ผู้เสนอราคา / ลูกค้าอนุมัติ
5. ลูกค้าตัดสินใจ → อนุมัติ / นัดวันมาทำ / ไม่อนุมัติ
6. ซ่อม → ตั้งศูนย์ → พร้อมส่ง → ส่งมอบ
```

## 3. สถาปัตยกรรม — ข้อจำกัดที่ต้องเคารพ

### 3.1 ไฟล์เดียวจบ (Single-file app)

ทั้งแอปอยู่ใน `index.html` ไฟล์เดียว — HTML + CSS + JS รวมกัน
**เหตุผล:** ผู้ใช้ไม่ใช่โปรแกรมเมอร์ ต้อง deploy ด้วยการลากไฟล์เดียว

### 3.2 ห้ามใช้ `type="module"` เด็ดขาด

โค้ดทั้งหมดใช้ `onclick="functionName()"` แบบ inline
ถ้าใส่ `type="module"` ฟังก์ชันจะหลุดออกจาก global scope → **ปุ่มทุกปุ่มในแอปตายหมด**

ดังนั้น Firebase ใช้ **compat SDK** ไม่ใช่ modular SDK:
```html
<script src="https://www.gstatic.com/firebasejs/10.12.2/firebase-app-compat.js"></script>
<script src="https://www.gstatic.com/firebasejs/10.12.2/firebase-auth-compat.js"></script>
<script src="https://www.gstatic.com/firebasejs/10.12.2/firebase-firestore-compat.js"></script>
```

### 3.3 รูปแบบการทำงาน: `state` + `view` + `render()`

```js
state = { jobs, vehicles, customers, models, masterParts, ... }  // ข้อมูลจริง (sync กับ Firestore)
view  = { tab, jobId, search, ci_* , je_*, ... }                 // สถานะหน้าจอ (ไม่ sync)
render()                                                          // วาดใหม่ทั้งหน้า
```

ทุกการกระทำ → แก้ `state` หรือ `view` → เรียก `render()`

**ข้อควรระวัง:** `render()` สร้าง DOM ใหม่ทั้งหมด → **iOS จะทิ้งแป้นพิมพ์**
ถ้าฟังก์ชันถูกเรียกจาก `oninput` ของช่องกรอกข้อความ **ห้ามเรียก `render()`**
(ดูข้อ 8.2 — เคยพลาดเรื่องนี้ 2 รอบ)

### 3.4 การบันทึกแบบ diff (`saveState` → `flushState`)

```js
shadow[col][id] = JSON string ของข้อมูลล่าสุดที่ตรงกับเซิร์ฟเวอร์
```

`flushState()` เทียบ `state` กับ `shadow` แล้ว**เขียนเฉพาะเอกสารที่เปลี่ยน**

**ทำไมสำคัญ:** ก่อนหน้านี้เขียนทับทั้งก้อน → 2 เครื่องแก้พร้อมกัน ข้อมูลหายทันที
วิธีนี้แก้ปัญหาโดยไม่ต้องแก้จุดเรียก `saveState()` ทั้ง ~100 จุด

ชื่อ เบอร์โทร อาการ และราคา ทั้งหมด

จึงสร้าง `board/{jobId}` แยก เก็บเฉพาะข้อมูลที่เปิดเผยได้:
คิว · ทะเบียน · จังหวัด · ยี่ห้อ · รุ่น · สี · รูปย่อ · ช่อง H · สถานะ · เวลาโดยประมาณ

คอยเก็บตกงานเก่าตอนล็อกอิน

### 4.4 Security Rules

ไฟล์ `firestore-rules.txt` → วางใน **Firebase Console → Firestore → Rules → Publish**

```
bootstrapAdmin()  // UID เจ้าของอู่ ฝังไว้กันล็อกเอาต์ตัวเอง + แก้ปัญหาไก่กับไข่ตอนสร้าง user แรก
hasAccess()       // ต้องมีเอกสารใน users/{uid} ถึงจะใช้ระบบได้
isAdmin()         // role == 'admin'
```

**สร้างบัญชีใน Authentication เฉยๆ ยังเข้าไม่ได้** — Admin ต้องเพิ่มสิทธิ์ในหน้าผู้ใช้งานก่อน

### 5.1 job (ใบงาน)

```js
{
  id, jobNumber: "PG260806-001", queueNo: "8",
  vehicleId, customerId,
  status: 'received',           // ดูข้อ 5.2

  bay: 'H3',                    // ช่องซ่อม

  complaints: [{ text, custom }],

  estUnit: 'minute', estValue: 180,   // ★ ระยะเวลาซ่อม (เก็บเป็นนาทีเสมอ)
  thumb: "data:image...",       // รูปย่อ 240px ติดมากับ job
  photoCount, photos: [],
  createdAt,
  deletedAt, deletedBy          // ★ มีค่า = อยู่ในถังขยะ (soft delete)

```

### 5.2 สถานะงาน (STATUS_FLOW)

```js
received   รับรถ         สีแดง
inspecting ตรวจเช็ค      สีส้ม
quoted     เสนอราคา      สีเหลือง     ← จุดตัดสินใจ แสดงปุ่ม 3 ปุ่มข้างล่าง
approved   อนุมัติ       ม่วง
scheduled  นัดวันมาทำ    (แยกออก → carout)
rejected   ไม่อนุมัติ    (แยกออก → carout)
repairing  กำลังซ่อม     ฟ้าอ่อน      ← ★ นาฬิกาเริ่มนับตรงนี้
aligning   รอตั้งศูนย์   ฟ้าเข้ม
ready      พร้อมส่ง      เขียวอ่อน    ← ★ นาฬิกาหยุดตรงนี้
delivered  ส่งแล้ว       เขียวเข้ม    ← ★ หลุดจากรายการงาน ไปหน้า "ส่งมอบแล้ว"
carout     เอารถลง       เทา
```

```js
MAIN_PATH   = ['received','inspecting','quoted','approved','repairing','aligning','ready','delivered']
DECISION_KEYS = ['approved','scheduled','rejected']   // ปุ่มที่โผล่เฉพาะตอนสถานะ quoted
BRANCH_ENDS = { scheduled:'carout', rejected:'carout' }
```

### 5.3 รูปภาพ — ทำไมต้องแยกเอกสาร

- รูปจากมือถือ 2–4 MB · Firestore จำกัดเอกสารละ **1 MB**
- แก้โดย: ย่อเหลือ ~1000px เก็บ **1 รูป = 1 เอกสาร** ใน `jobPhotos` โหลดเมื่อเปิดดูเท่านั้น
- รูปย่อ ~240px (`job.thumb`) ติดไปกับ job เพื่อให้การ์ดในรายการงานขึ้นทันที
- จำกัด 6 รูป/งาน (`MAX_PHOTOS_PER_JOB`)

### 6.2 กระดานสถานะลูกค้า (`?board`)

- เปิดจาก QR ที่ห้องรับรอง **ไม่ต้องล็อกอิน**
- นาฬิกาเดินวินาที · แยกตามวันที่รับรถ · ผังช่องทำงาน
- แต่ละคัน: คิว · รูป · ยี่ห้อรุ่น · สี · ป้ายทะเบียน · สถานะ · ช่อง H · **นาฬิกานับถอยหลัง**
- **ไม่แสดง:** ชื่อ เบอร์โทร อาการ ราคา

### 6.3 ระยะเวลาซ่อม + นาฬิกาเรียลไทม์ (v3.8–3.9)

**การตั้งค่า:** กล่อง **วัน : ชั่วโมง : นาที** มีปุ่ม +/− (วัน ±1, ชม. ±1, นาที ±5)
ข้างๆ มีปุ่ม **ตั้งเอง** เปิด dropdown เลือกตัวเลข (วัน 0–30 · ชม. 0–23 · นาที 0–55 ทีละ 5)

**เก็บเป็นนาทีเสมอ** (`estUnit:'minute'`, `estValue:` จำนวนนาที)

**นาฬิกา 4 สถานะ:**

| ตอน | แสดง |
|---|---|
| ยังไม่เริ่มซ่อม | เทา · "ประมาณ 3 ชม." |
| กำลังซ่อม | เขียว · "เหลืออีก 1 ชม. 12 น. 07 ว." + "เสร็จประมาณ 14:05:22 น." + แถบวิ่ง |
| เกินเวลา | แดง · "เลยเวลา 25 น. 10 ว." + "กำหนดเดิม 14:05:22 น." |
| เสร็จแล้ว | เขียวหยุดนิ่ง · "ซ่อมเสร็จแล้ว · ใช้เวลา 4 ชม. 10 น." |

**หัวใจสำคัญ — `repairCycle(job)`:**
อ่าน **รอบล่าสุด** เท่านั้น (หา `'repairing'` ครั้งหลังสุดใน `statusHistory`
แล้วหาจุดจบเฉพาะที่เกิดหลังจากนั้น) — ถ้าอ่านครั้งแรกสุด รถที่เคยส่งแล้วดึงกลับมา
จะโชว์เวลารอบเก่าและนาฬิกาไม่เดิน (เคยเป็นบั๊กจริง แก้ไปใน v3.8.4)

**อัปเดตสด:** กระดานลูกค้า `setInterval(tickBoardClock, 1000)` · แอปพนักงาน `setInterval(tickBoardEta, 1000)`
ทั้งคู่เขียนทับเฉพาะ text ไม่เรียก `render()` (ไม่งั้นแป้นพิมพ์/ช่องค้นหาโดนรีเซ็ต)

### 6.4 ลบแบบกู้คืนได้ (Soft delete, v3.6)

- กดลบ = ใส่ `deletedAt` + `deletedBy` ไม่ได้ลบจริง · ปล่อยช่อง H ทันที · เอาออกจาก `board`
- ทุกที่ที่แสดงรายการงานต้องผ่าน **`activeJobs()`** (กรอง `deletedAt` ออก)
- ถังขยะอยู่ที่ **เมนูผู้ใช้ → ประวัติการลบ** กู้คืนได้ทุกคน · **ลบถาวรเฉพาะ Admin**

### 6.5 ค้นหา (v3.7.3)

`jobSearchBlob(job)` รวมทุกอย่างเป็นสตริงเดียว:
Job No. · คิว · ช่อง H · ทะเบียน (ทั้งมีและไม่มีเว้นวรรค) · จังหวัด · ยี่ห้อ · รุ่น · ปี · สี · ชื่อ · เบอร์

พิมพ์หลายคำได้ เรียงยังไงก็ได้ (`honda ขาว` = `ขาว honda`)

### 6.6 บันทึกร่างหน้ารับรถ (v3.5)

เก็บใน `localStorage` key `gsms-checkin-draft` (`CI_DRAFT_FIELDS`)
ออกจากหน้ากลางคัน → ถาม "บันทึกร่างไว้ / ไม่บันทึก"

### 6.7 อื่นๆ

- **ป้ายทะเบียน** วาดให้เหมือนของจริง (`plateHtml`)
- **ธีม** เปลี่ยนสีทั้งแอปได้ (`THEME_PRESETS`)
- **สำรองข้อมูล** ดาวน์โหลด/นำเข้า JSON + File System Access API (จำที่บันทึกไว้)
- **QR Code** สร้าง/พิมพ์ป้าย QR สำหรับติดห้องรับรอง
- **สรุปลงไลน์** สร้างข้อความพร้อมคัดลอกส่งลูกค้า

## 8. บั๊กที่เคยเจอ — อย่าทำซ้ำ

### 8.1 `confirm()` / `prompt()` ของเบราว์เซอร์ไม่ทำงานบน iOS
ปุ่มลบกดแล้วเงียบสนิท → สร้าง `uiConfirm`/`uiPrompt` เป็น modal ในแอปแทน **ห้ามกลับไปใช้ของเดิม**

### 8.2 แป้นพิมพ์ iOS เด้งกลับทุกตัวอักษร (พลาด 2 รอบ)
- ครั้งแรกโทษ `autocapitalize` → **ผิด**
- สาเหตุจริง: `oninput` เรียก `render()` ทุกครั้ง → DOM ถูกสร้างใหม่ → iOS ทิ้ง layout แป้นพิมพ์
- **แก้:** อย่าเรียก `render()` จาก `oninput` ให้แก้ DOM ตรงจุดแทน (ดู `onDeliveredSearch`, `onSearchInput`)
- คืน caret ได้ แต่คืนแป้นพิมพ์ไม่ได้

### 8.3 นาฬิกาค้าง / ไม่รีเซ็ต (v3.8.4)
อ่าน `'repairing'` ครั้ง**แรก**ใน `statusHistory` → รถที่เคยส่งแล้วดึงกลับมาโชว์เวลารอบเก่า
**แก้:** `repairCycle()` อ่านรอบล่าสุดเท่านั้น

### 8.4 `addUserAccess` เขียนทับ user เดิม
ใช้ `set()` โดยไม่เช็คว่ามีอยู่แล้ว → เจ้าของอู่เสียสิทธิ์ Admin ตัวเอง
**แก้:** เช็คก่อน + มี `repairBootstrapAdmin()` กู้คืน

### 8.5 แยกยี่ห้อ/รุ่นผิด (`ยี่ห้อ ACCORD / รุ่น GEN8`)
เดายี่ห้อจากคำแรกของชื่อรุ่น → **แก้:** อ่านจาก record ตรงๆ ใช้ ID เป็น key ไม่ใช่ชื่อ

### 8.6 พิมพ์ไม่ได้บน iOS แบบ Add to Home Screen
`window.print()` ไม่ทำงานใน standalone mode และไม่มีทางแก้ด้วย JS
**แก้:** ตรวจด้วย `isStandalone()` แล้วเสนอ "เปิดใน Safari"

### 8.7 กระดานลูกค้าว่างเปล่าทั้งที่มีรถ 23 คัน
`board` เขียนเฉพาะตอน save → งานเก่าไม่เคยขึ้น
**แก้:** `reconcileBoard()` รันครั้งเดียวหลังล็อกอิน + มีปุ่มสั่งเองในตั้งค่า

### 8.8 การนับวันผิดวัน
ตัดสตริง ISO ตรงๆ = นับตาม UTC → งานหลัง 07:00 น. ไทยไปโผล่วันถัดไป
**แก้:** ใช้ `dayKey()` ที่อ่านเวลาท้องถิ่น

### 8.9 VM (bash) ล่มบ่อย
ทำให้คัดลอก/เปลี่ยนชื่อไฟล์ไม่ได้หลายรอบ → **ตกลงกันว่าแก้ `index.html` ตรงๆ ไม่ต้องทำสำเนา**

## 9. กฎการเขียนโค้ดในโปรเจกต์นี้

1. **ภาษาไทยทั้งหมดใน UI** — ทั้งข้อความ ปุ่ม และใบพิมพ์
2. **ยี่ห้อ/รุ่น/ทะเบียน = ตัวพิมพ์ใหญ่เสมอ** (บังคับด้วย JS ไม่ใช่แค่ CSS)
3. **วันที่รูปแบบ DD/MM/YYYY** · ปี พ.ศ. ในใบพิมพ์
4. **Responsive 3 ระดับ** ใช้ `pointer:coarse` ร่วมกับความกว้าง
   (ความกว้างอย่างเดียวแยก iPad Pro แนวนอน 1366px กับโน้ตบุ๊กไม่ได้)
   - คอม 2–4 คอลัมน์ · iPad 1–3 · มือถือ 1
5. **มือถือมาก่อน** — ปุ่มใหญ่พอกดด้วยนิ้ว มีแถบแท็บล่างจอ
6. **คอมเมนต์อธิบาย "ทำไม" ไม่ใช่ "ทำอะไร"** — โค้ดนี้มีคอมเมนต์เยอะเพราะบั๊กหลายตัวไม่ชัดเจน
7. **ใบพิมพ์ต้องไม่มี URL/path** ของเบราว์เซอร์
8. **อัป `APP_VERSION` ทุกครั้ง**

## 10. งานที่ยังค้าง
